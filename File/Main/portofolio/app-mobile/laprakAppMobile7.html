Checkpoint 1 & 2: Assets dan Image Network

Checkpoint 1: Asset Gambar dan Custom Font

Tampilan awal aplikasi yang telah mengimplementasikan custom font Poppins untuk seluruh tipografi serta menambahkan asset lokal berupa logo aplikasi pada AppBar.

Checkpoint 2: ListView dan Image.network

Penerapan ListView.builder untuk merender daftar resep secara dinamis, dilengkapi dengan pengambilan gambar (thumbnail) dari internet menggunakan Image.network.

Checkpoint 2b: Error State Gambar

Pengujian errorBuilder pada pemuatan gambar dari internet. Saat gambar gagal dimuat (misal karena URL tidak valid atau jaringan terputus), aplikasi memunculkan gambar placeholder berupa ikon piring dari asset lokal alih-alih menampilkan error merah yang merusak UI.

Langkah C.3: Perhitungan Grid Kartu

Tampilan Halaman Detail dengan Porsi Aktif

Halaman detail resep yang telah diperbarui, menampilkan foto makanan dengan proporsi besar di bagian atas.

1. Menghitung Lebar Kartu (dp)

Pertama, kurangi lebar layar dengan semua padding dan spacing, lalu bagi sisanya dengan jumlah kolom.
Total Ruang Tersedia = Lebar Layar - Total Padding - Spacing Antar Kolom
Total Ruang Tersedia = 360 dp - (8 dp + 8 dp) - 8 dp
Total Ruang Tersedia = 360 - 16 - 8 = 336 dp
Lebar per kartu = Total Ruang Tersedia / Jumlah Kolom
Lebar per kartu = 336 / 2 = 168 dp

2. Menghitung Tinggi Kartu (dp)

Setelah lebar kartu diketahui (168 dp), gunakan rumus rasio childAspectRatio (Lebar : Tinggi = 3 : 4).
Rasio = Lebar / Tinggi
Tinggi = Lebar / Rasio
Tinggi = 168 / (3 / 4)
Tinggi = 168 * (4 / 3) = 224 dp

Yang Dihitung Hasil
Lebar Kartu ( dp ) 168
Tinggi Kartu ( dp ) 224

Checkpoint 3: Mode Grid dan Transisi Detail

Tampilan GridView dengan Tombol Toggle

Perubahan antarmuka menjadi mode grid melalui GridView.builder. Aplikasi kini menampilkan resep berupa kartu dua kolom dengan rasio aspect 3:4. Status favorit (ikon hati merah) disinkronkan secara global dari Provider.

Akses Detail dari Mode Grid

Kartu resep pada antarmuka grid telah dibungkus menggunakan InkWell sehingga dapat ditekan untuk melakukan transisi navigasi menuju layar detail dengan mempertahankan identitas resep yang dipilih.

Latihan 1, 2, & 3

Latihan 1: ChoiceChip Filter Kategori (Cuisine)

Implementasi fitur penyaringan resep masakan berbasis kategori menggunakan widget ChoiceChip horizontal yang ditempatkan persis di bawah AppBar.

Latihan 2: Manajemen Halaman Favorit dengan Dismissible

Pembaharuan halaman favorit yang kini menyertakan fitur usap (swipe) untuk menghapus menggunakan widget Dismissible, lengkap dengan notifikasi peringatan (SnackBar).

Latihan 3: CustomScrollView dan SliverAppBar

Pemugaran tampilan halaman detail menggunakan CustomScrollView. Konfigurasi ini menyematkan foto sebagai background SliverAppBar yang akan berinteraksi responsif mengecil menyesuaikan sapuan layar ketika halaman di-scroll ke bawah.

Pertanyaan Analisis

Mengapa status favorit tetap sama di grid dan list?
Status favorit tetap sama karena data favorit tidak disimpan di dalam rancangan widget RecipeGridCard atau RecipeTile, melainkan disimpan secara terpusat di FavoriteProvider seperti yang dipelajari pada Modul 6. Karena kedua widget tersebut hanya bertugas menampilkan ("watch") data dari sumber Provider yang sama, maka penambahan favorit di tampilan grid akan otomatis terbaca saat kita pindah ke tampilan list.
Apa akibatnya jika baris if (loadingProgress == null) return child; dihapus?
Jika baris tersebut dihapus, maka foto asli dari internet tidak akan pernah muncul di layar dan aplikasi hanya akan menampilkan ikon loading (gambar garpu dan sendok) terus-menerus. Hal ini terjadi karena baris tersebut adalah kunci yang memerintahkan aplikasi untuk memunculkan gambar asli (child) saat proses unduhannya sudah selesai (ditandai dengan nilai loadingProgress yang kosong/null).
Hitungan pixel dan dampaknya pada memori?
Tanpa cacheWidth, satu foto diproses sebesar 960.000 pixel ($1200 \times 800$), sedangkan dengan cacheWidth: 168 (tinggi foto akan menyesuaikan proporsinya menjadi 112), aplikasi hanya memproses 18.816 pixel ($168 \times 112$). Jika diaplikasikan pada 50 resep di Modul 8 tanpa cacheWidth, memori HP (RAM) akan cepat penuh dan membuat aplikasi menjadi sangat lag atau bahkan tertutup sendiri (force close) karena harus memproses hampir 50 juta pixel secara bersamaan.
Alasan pemilihan Asset vs Network
Logo aplikasi menggunakan Image.asset (penyimpanan lokal) agar bisa langsung muncul secara instan saat aplikasi dibuka tanpa harus menunggu koneksi internet. Sebaliknya, foto resep menggunakan Image.network dari internet agar ukuran file pemasangan aplikasi (APK) tidak menjadi sangat besar dan berat, mengingat jumlah foto resep yang banyak dan datanya bisa bertambah sewaktu-waktu.
